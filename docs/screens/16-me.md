# 16 — Me

## Product + implementation contract

Me is the durable account home ordered by urgency: Active now, Orders, Memberships & passes, Tickets, Wallet, then Profile & settings. Active now only appears for a non-terminal relay-derived order and uses a plain status summary such as **Ready for pickup**; the stable order reference remains internal navigation data rather than headline copy. Ticket counts use customer language such as **1 saved ticket**, never transport or protocol confirmation terms. Rows never imply ownership from an offer; entitlement ownership requires kind 8 for the local pubkey. Wallet reports unavailable until verified NIP-60 state exists.

States include signed-in empty, active order, active credential, action-needed membership, no selected room, relay loss with cached signed records, protected-store failure, and account recovery. Every row has at least a 48dp target and text status rather than color-only meaning.

## Complete QA strategy

`.qa/qa-16-me.mjs` joins the reserved relay with a deterministic identity and requires its exact order projection before asserting information order, plain status copy, hidden internal reference, and navigation. Independent verification still matches the exact signed award and status IDs; teardown sweeps scenario fixtures. Unit tests invoke every destination and prove the active card omits its reference. Native coverage includes no active item, each urgent card, multiple durable objects, offline reopening, long localized names, maximum text scale, screen-reader traversal, and no fifth Wallet tab.

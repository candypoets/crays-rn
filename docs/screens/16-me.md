# 16 — Me

## Product + implementation contract

Me is the durable account home ordered by urgency: current room, Active now, Orders, Memberships & passes, Tickets, Wallet, then Profile & settings. Entry is through the **Me** primary tab or by returning from one of its durable child screens. When an active room session exists, its signed room name appears in a full-card button; pressing anywhere on that card navigates through the tab router to the existing Room screen. This changes only the selected primary tab: it does not join again, publish presence, replace the manager, or start a second room subscription. If the room session ends between rendering and the press, the Room route owns the existing automatic-end or Discover redirect.

Active now only appears for a non-terminal relay-derived order and uses a plain status summary such as **Ready for pickup**; the stable order reference remains internal navigation data rather than headline copy. Ticket counts use customer language such as **1 saved ticket**, never transport or protocol confirmation terms. Rows never imply ownership from an offer; entitlement ownership requires kind 8 for the local pubkey. Wallet reports unavailable until verified NIP-60 state exists.

States include signed-in empty, active order, active credential, action-needed membership, no selected room, relay loss with cached signed records, protected-store failure, and account recovery. The current-room card stays available during relay loss while the local active session still exists, allowing the Room screen to show its own disconnected state. With no active session, **No room selected** is a static status card and must not expose a button role or navigate using an archived order venue.

The active current-room card is at least 96dp tall, exposes the room name and **You’re inside** in its accessibility label, announces itself as a button with the **Return to room** action, and includes a visible chevron so interactivity is not conveyed by color alone. Its room name may wrap or shrink within the flexible text column at large text sizes. Navigation is immediate and requires no relay acknowledgement; relay and protected-store errors remain visible on Me until the user leaves the screen.

## Complete QA strategy

`.qa/qa-16-me.mjs` joins the reserved relay with a deterministic identity and requires its exact order projection. Maestro opens Me, presses the active current-room card, waits for the existing Room screen, returns through the Me tab, and then asserts information order, plain status copy, hidden internal reference, and durable navigation. Independent verification still matches the exact signed award and status IDs; teardown sweeps scenario fixtures. Unit tests invoke the current-room destination and every durable destination, prove the current-room empty state is not actionable, and prove the active order card omits its reference. Native coverage includes no active item, each urgent card, multiple durable objects, offline reopening, long localized names, maximum text scale, screen-reader traversal, and no fifth Wallet tab.

## Night Playlist implementation

The bright account drawer follows board 04 panel 01: a large **Me** title, a signed-current-room image card, a compact active-order rail, then one quiet durable ledger for Orders, Memberships & passes, Tickets, Wallet, and Messages. Profile & settings remains a separate, large-text-safe final destination. **You’re inside** is shown only for the active room session; an archived order venue can never supply that claim. When several orders are active, Ready outranks Preparing, Accepted, and Sent, followed by newest trusted status and stable ID. Membership-ready copy requires a currently usable trusted kind-8 entitlement; a cached invite redemption or revoked/exhausted record cannot produce it. Protected archive/ticket hydration says **Loading** and a live relay refresh says **Refreshing**; neither may emit confirmed-empty copy. Relay loss labels the visible records as saved data. The decorative notification mark is hidden from assistive technology until a real notification action exists. Missing room, ticket, membership, and wallet data is stated directly only after its source settles; no local optimistic count or balance is substituted.

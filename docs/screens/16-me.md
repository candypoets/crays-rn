# 16 — Me

## Product + implementation contract

Me is the durable account home. It first answers **which Crays profile is active on this device**, then orders the night by urgency: current room, Active now, Orders, Memberships & passes, Tickets, Wallet, Messages, then Settings & privacy. Entry is through the **Me** primary tab or by returning from one of its durable child screens. When an active room session exists, its signed room name appears in a full-card button; pressing anywhere on that card navigates through the tab router to the existing Room screen. This changes only the selected primary tab: it does not join again, publish presence, replace the manager, or start a second room subscription. If the room session ends between rendering and the press, the Room route owns the existing automatic-end or Discover redirect.

The profile pass is sourced only from one validated read of the protected local identity and its signed kind-0 metadata. It shows the kind-0 `picture` when it is a valid HTTP(S) URL, otherwise a deterministic pubkey-derived bundled portrait; the display name; **Your Crays identity**; an abbreviated `npub`; and **Protected on this device**. It never sources self identity from the active room profile map and never puts `nsec`, signer bytes, or the raw signed event in React state. The whole compact pass is one button. Opening it expands **Public identity**, the full selectable `npub`, and the explanation **This is the name rooms see when you choose to be visible. Your secret key is never shown here.** No nested Edit or Copy control is placed inside the button.

The pass describes a local Nostr identity, not an email/provider session or a globally verified person. It must not say **Signed in**, **Public profile**, **Published**, or **Verified**. Editing, logout/lock, provider recovery, identity removal, and explicit clipboard copy are not exposed as working actions: there is no end-to-end custody/session contract for them, and the current reset helper does not clear every identity-owned cache or the native signer. The existing settings destination is therefore named **Settings & privacy**, not a duplicate **Profile & settings** action.

Active now only appears for a non-terminal relay-derived order and uses a plain status summary such as **Ready for pickup**; the stable order reference remains internal navigation data rather than headline copy. Ticket counts use customer language such as **1 saved ticket**, never transport or protocol confirmation terms. Rows never imply ownership from an offer; entitlement ownership requires kind 8 for the local pubkey. Wallet reports unavailable until verified NIP-60 state exists.

Account states are independent from ticket, order, entitlement, and relay states. Initial protected-account loading keeps a fixed-height **Loading your profile…** pass and invents no avatar/name. A valid identity without a signed profile says **Finish your profile**. Fully absent account material says **No Crays identity on this device**. Partial, mismatched, corrupt, malformed-metadata, or invalid-signature state says **Profile could not be verified** and never generates a replacement identity. A rejected protected-store read says **Profile unavailable** with one 48dp **Try again** action; it does not treat a temporarily locked iOS Keychain as logout, erase state, or route to onboarding. A refocus/retry generation guard prevents an older read from overwriting a newer result.

Durable states include empty, active order, active credential, action-needed membership, no selected room, relay loss with cached signed records, protected-store failure, and account recovery. Non-secret order and entitlement snapshots coalesce while iOS is inactive, write serially only after the app is active, and retry their latest values on the next foreground transition. A rejected native write becomes the existing protected-storage error state instead of an unhandled promise; a successful retry clears that write error. The current-room card stays available during relay loss while the local active session still exists, allowing the Room screen to show its own disconnected state. With no active session, **No room selected** is a static status card and must not expose a button role or navigate using an archived order venue.

The profile pass is at least 112dp tall with a 80dp portrait and one 48dp+ disclosure target. Its accessible label combines display name, **Your Crays identity**, custody status, and **View profile**/**Hide profile**; the portrait is decorative within that label. Display names wrap rather than truncate. At large text sizes, metadata and the visible disclosure affordance may grow vertically without covering Current room or the bottom navigation. Expanded identity text is selectable and can wrap without horizontal scrolling. The active current-room card remains at least 96dp tall, exposes the room name and **You’re inside** in its accessibility label, announces itself as a button with the **Return to room** action, and includes a visible chevron so interactivity is not conveyed by color alone. Its room name may wrap or shrink within the flexible text column at large text sizes. Navigation is immediate and requires no relay acknowledgement; relay and protected-store errors remain visible on Me until the user leaves the screen.

## Complete QA strategy

`.qa/qa-16-me.mjs` joins the reserved relay with a deterministic identity and requires its exact order projection. Maestro opens Me, asserts the seeded signed local name and custody language, expands the pass, checks the exact full fixture `npub`, presses the active current-room card, waits for the existing Room screen, returns through the Me tab, and then asserts information order, plain status copy, hidden internal reference, and durable navigation. `.qa/verify-me-local-profile.mjs` independently matches the public-only native marker to the deterministic fixture pubkey, `npub`, display name, completed state, and device-only custody; existing independent relay verification still matches the exact room, award, and status IDs. Teardown sweeps scenario fixtures. Unit tests validate one-generation SecureStore reads, identity/signature/metadata validation, safe picture handling, no secret projection, Keychain rejection, every profile state, expansion, current-room behavior, and every durable destination. Native coverage includes no active item, each urgent card, multiple durable objects, offline reopening, long localized names, maximum text scale, screen-reader traversal, and no fifth Wallet tab.

## Night Playlist implementation

The bright account drawer extends board 04 panel 01 with the profile-card placement from the earlier canonical Me studies: a large **Me** title, one compact white identity pass, a signed-current-room image card, a compact active-order rail, then one quiet durable ledger for Orders, Memberships & passes, Tickets, Wallet, and Messages. This is a Night Playlist translation, not a return to the retired dark palette. The pass uses only semantic lilac/white/plum/blue roles, a pubkey-stable portrait, thin edge, and no verification color. **Settings & privacy** remains a separate, large-text-safe final destination. **You’re inside** is shown only for the active room session; an archived order venue can never supply that claim. When several orders are active, Ready outranks Preparing, Accepted, and Sent, followed by newest trusted status and stable ID. Membership-ready copy requires a currently usable trusted kind-8 entitlement; a cached invite redemption or revoked/exhausted record cannot produce it. Protected archive/ticket hydration says **Loading** and a live relay refresh says **Refreshing**; neither may emit confirmed-empty copy. Relay loss labels the visible records as saved data. The decorative notification mark is hidden from assistive technology until a real notification action exists. Missing room, ticket, membership, and wallet data is stated directly only after its source settles; no local optimistic count or balance is substituted.
